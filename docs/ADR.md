# Architecture Decision Records

## 철학

**지식 베이스의 가치는 크기가 아니라 신뢰성이다.** 틀린 residue 번호 하나, 맥락 없는 IC50 하나가 에이전트를 자신 있게 틀리게 만든다. 그래서 다음을 우선한다.

1. **검증 가능한 것과 아닌 것을 섞지 않는다.** 기계가 확인한 것, 사람이 승인한 것, LLM이 추측한 것은 각각 다른 필드에 남는다.
2. **모르는 것은 모른다고 적는다.** 조용히 그럴듯한 값을 내놓느니 `unknown` · `unmapped` · `conflict`를 반환한다.
3. **모든 주장은 원문까지 역추적된다.** 근거 없는 레코드는 들어오지 못한다.
4. **실제 병목만 자동화한다.** 쓰이지 않을 범용 기반을 먼저 짓지 않는다.

---

### ADR-001: Design Move를 지식의 원자 단위로 삼는다
**결정**: `구조적 관찰 → 화학적 변형 → 측정 효과 → 트레이드오프 → 근거` 한 덩어리를 1급 객체로 둔다. Case(화합물 시리즈)나 Rule(일반화된 규칙)이 아니다.
**이유**: 최종 소비자가 요구하는 것이 "다음에 무엇을 바꿀까"이므로, 검색 단위가 곧 변형 단위여야 한다. Case는 조회 단위가 너무 커서 관련 부분만 뽑기 어렵고, Rule은 일반화 과정에서 LLM이 과장하며 역추적이 끊긴다.
**트레이드오프**: 프로그램 전체의 서사와 맥락이 흩어진다. 타겟별·테마별 묶음은 `dist/`에서 파생 뷰로 만든다.

### ADR-002: 태그는 SITE / GOAL / TACTIC 3축만 쓴다
**결정**: 통제 어휘를 세 축으로 고정한다. `gk_class`, `mechanism_class` 같은 값은 태그가 아니라 typed field로 둔다. 구조의 상태(점유·열림 여부)도 태그가 아니라 descriptor 필드다.
**이유**: SITE 단일 축은 site가 없는 변형(물성 개선, 매크로사이클화, bioisostere)을 담지 못한다. 실제 med-chem 최적화의 상당 부분이 그렇다. 또한 **에이전트의 출력이 사는 축이 TACTIC이다** — 에이전트는 부위가 아니라 화학적 조작을 제안한다. 입력 축만 색인하면 출력 쪽을 조회할 수 없다.
**트레이드오프**: 태그와 필드의 경계를 매번 판단해야 한다. `docs/ONTOLOGY.md`에 기준을 적고 검증기가 강제한다.

### ADR-003: 구조적 사실은 DB에서, 설계 논리는 논문에서 받는다
**결정**: residue 번호, 도메인 경계, DFG/αC 상태, 변이 위치는 외부 DB에서만 온다. LLM은 구조적으로 검증 가능한 주장을 담당하지 않는다. LLM이 채우는 값은 원문의 글자 그대로의 부분문자열(`span`)을 근거로 달아야 하고, 없으면 버린다.
**이유**: LLM은 residue 번호와 DFG 상태를 자신 있게 지어낸다. 그리고 그건 정확히 틀렸을 때 가장 해로운 값이다. 캡션으로는 추론 불가능한 것을 추론하게 두지 않는다.
**트레이드오프**: DB에 없는 구조(사내 구조, 미등재 PDB)는 상태값이 비어 있다. 소비자가 제공한 descriptor를 쓰거나 `unknown`이다.

### ADR-004: review_status · checks_passed · confidence를 분리하고, 사람 승인만이 kb/ 진입 요건이다
**결정**: 세 필드를 독립시킨다. 한 필드가 다른 필드를 자동으로 결정하지 않는다. 기계 검사 통과는 승격 사유가 아니라 **리뷰 큐의 정렬 신호**다. `confidence`는 사람만 부여한다.
**이유**: PMID·PDB가 실재하고 숫자가 원문에 등장한다는 사실은 "관찰 → 변형 → 효과"의 연결이 옳다는 증거가 아니다. 초안은 기계 검사 통과를 `confidence: medium`으로 변환했는데 이는 범주 오류였고, 여기서 파생된 모순이 문서 전반에 퍼졌다.
**트레이드오프**: 사람 검수가 처리량의 상한이 된다. 이를 승격 기준을 느슨하게 해서가 아니라 **테마별 리뷰·우선순위·중복 억제**로 푼다. 이 둘을 섞지 않는 것이 핵심이다.

### ADR-005: kb / ref / dist의 소유권을 분리한다
**결정**: `kb/`는 사람이 승인한 지식, `ref/`는 사람이 수정하지 않는 외부 고정 snapshot, `dist/`는 빌드 산출물이다. **빌드는 `kb/`를 수정하지 않는다.**
**이유**: 재생성 의미가 정반대다. `kb/`는 대체 불가고 `ref/`는 지워도 된다. 섞으면 `rm -rf && rebuild`를 영영 못 한다. 더 중요하게는 파생 테이블이 갱신마다 수천 행 요동쳐 `git log kb/`를 기계 소음으로 덮는다. 그러면 "무엇을 언제 누가 승인했는가"를 답할 수 없고, 사람 게이트를 두는 이유가 사라진다.
**트레이드오프**: 디렉터리가 늘고 소비자가 여러 파일을 본다. `dist/`의 비정규화로 상쇄한다.

### ADR-006: KLIFS는 pocket 정의로만 쓰고, 구조 상태는 Kincore에서 받는다
**결정**: KLIFS의 85위치 해부 라벨과 kinase별 pocket 서열은 고정 snapshot으로 온톨로지의 근거로 삼는다. per-structure 상태(DFG/αC)의 1차 소스는 Kincore로 옮긴다.
**이유**: 4개 kinase 표본(EGFR·ABL1·CDK2·BTK)에서 KLIFS는 2025년 이후 구조 167건 중 0건을 담고 있었다. 2023–2024는 잘 덮여 있다. 에이전트가 판단할 복합체는 최신 구조이거나 사내 구조이므로, 거기서 KLIFS 조회는 빈손으로 돌아온다. 반면 pocket 정의는 거의 변하지 않는 레퍼런스라 정체가 문제되지 않는다.
**트레이드오프**: 두 소스의 필드 의미가 같은지 확인해야 한다. **Kincore의 αC 분류가 KLIFS `ac_helix`와 같은 의미인지 아직 확인하지 않았다.** 확인 전까지 두 값을 합치지 않고 병기한다.

### ADR-007: 위치 매핑은 지원 target에 한정하고, 나머지는 unmapped를 반환한다
**결정**: v1은 검수된 `KLIFS position ↔ reference(UniProt canonical) position` 표를 지원 target에만 둔다. 지원 밖 target과 모호한 정렬은 `unmapped`다. 갭에는 `not_observed` / `not_applicable` / `unmapped` 원인을 붙인다.
**이유**: 85개 위치에 라벨을 붙이는 일과, 임의 입력에서 그 위치를 정확히 찾는 일은 다르다. KLIFS는 구조 정렬 기반 master alignment를 쓴다. 짧은 pocket 문자열의 단순 정렬로 범용 매퍼가 검증됐다고 볼 수 없다.
**트레이드오프**: 커버리지가 좁다. 범용 매퍼는 실제 요구가 생겼을 때 별도 확장 단계로 만든다. 조용히 틀린 residue를 내놓는 것보다 좁은 게 낫다.

### ADR-008: residue 참조에 numbering_scheme을 필수로 하고, WT 검사와 mutant 검사를 나눈다
**결정**: 모든 residue 참조가 `numbering_scheme`을 갖는다. 기본값은 없다. 매핑 검증은 WT 구조에 WT residue를, mutant 구조에 mutant residue를 기대한다.
**이유**: ABL1 gatekeeper는 구조마다 답이 다르다. PDB 2hyy는 315(ABL1a 번호), 6xr7은 334(ABL1b)다. 번호만으로 역산하면 T315를 gatekeeper가 아닌 `b.l.33`으로 잘못 찍는 것을 실제로 재현했다. 그리고 초안의 "아미노산 정체성 검증"은 T315I 구조에서 T를 요구해 **정상 변이 구조를 거부하는 버그**였다.
**트레이드오프**: 큐레이터가 매번 번호 체계를 확인해야 한다. 그게 목적이다. 아미노산 하나의 일치는 필요조건이지 충분조건이 아니므로 주변 정렬·도메인·복수 앵커를 함께 본다.

### ADR-009: 효과를 실험 맥락에 고정하고, 부등호 값에는 배수를 계산하지 않는다
**결정**: 측정값마다 `(pmid, 표/그림, 행/열, 화합물, target/variant, assay, metric, value, unit, qualifier, 각주)`를 붙인다. 같은 조건임이 확인되지 않은 before/after 쌍에는 비교를 만들지 않는다. 부등호가 있으면 `fold_change`를 null로 두고 `fold_change_bound`에 하한을 보존한다.
**이유**: 원문에 `11`이 있다는 것은 그 `11`이 이 화합물의 이 assay 값이라는 뜻이 아니다. 초안은 `>10000`과 `=11`로 `fold_change: 909`를 계산했는데, 이는 하한을 정확값으로 바꾼 것이다. 표 각주를 버리면 assay 조건과 부등호 의미도 함께 사라진다.
**트레이드오프**: 레코드가 길어지고 큐레이션이 느려진다. 수치가 이 KB의 가치이므로 받아들인다. `span_present`(기계)와 `source_checked`(사람)를 나눠 전자를 검수로 오해하지 않게 한다.

### ADR-010: 구조 참조는 pdb_id + chain + ligand_id로 하고, 그림 상태는 패널 단위로 붙인다
**결정**: 구조 참조의 최소 단위를 `{pdb_id, chain, ligand_id}`로 한다. 그림의 상태는 정확히 연결된 패널에만 붙이고, 복합 그림의 상태를 하나로 합치지 않는다. 소스가 충돌하면 양쪽 원값과 기준을 보존하고 `conflict`로 표시한다.
**이유**: 한 그림에 여러 패널과 여러 구조가 들어간다. `PDB-3OXZ` 하나로는 어느 chain·ligand·패널인지 부족해 다른 복합체의 상태가 붙을 수 있다. 또한 초안의 CI 규칙은 사람이 수정한 값을 기계값으로 덮었는데, 이는 검수를 무력화한다.
**트레이드오프**: 참조가 장황해지고 그림 큐레이션 비용이 는다. 출처(provenance)와 검수 상태를 분리해 관리한다.

### ADR-011: ID는 최초 승인 시 고정하고, content_hash는 변경 감지로만 쓴다
**결정**: 승인 시 순차 ID(`MOVE-0001`)를 부여하고 영구 유지한다. `content_hash`는 변경 감지 전용이고, 인용에는 revision을 포함한다. 후보 중복은 `(paper, 표/그림 위치, 화합물 쌍)`으로 탐지한 뒤 사람이 확인한다.
**이유**: 내용 해시 ID는 문구만 고쳐도 바뀌어 mutation·figure·인용 연결이 끊긴다. 반대로 같은 ID의 수치가 바뀔 수 있어 ID만으로 해석 버전이 고정되지도 않는다. 거부 원장도 문구가 바뀌면 동일 후보를 놓친다.
**트레이드오프**: ID 발번기와 revision 관리가 필요하다. 근사 중복 엔진은 만들지 않는다.

### ADR-012: 파일 계약만 제공하고, 임베딩·질의 DSL·MCP를 도입하지 않는다
**결정**: `dist/`에 JSONL과 `CONTRACT.md`를 두고 stdlib 읽기 라이브러리 하나를 제공한다. 수치 필터는 파이썬 콜러블이거나 `jq`다. 벡터 인덱스, 질의 언어, MCP 서버를 만들지 않는다.
**이유**: 레코드가 수백~수천 규모라 전수 스캔이 밀리초다. 임베딩은 재현성과 설명 가능성을 잃고 의존성을 더한다. 질의 DSL은 파이썬 콜러블과 jq 사이에 낄 자리가 없다. MCP는 전송이지 기능이 아니라 소비자 대부분이 얻는 게 없다.
**트레이드오프**: 자유 텍스트 의미 검색이 안 된다. 별칭 정규화로 대체하고, 실제 병목이 되면 그때 넣는다. MCP가 유일하게 더하는 것은 이미지를 content block으로 반환하는 것이므로 `dist/`가 안정된 뒤 얇은 래퍼로 붙인다.

### ADR-013: 실행 순서를 수동 Move 우선으로 뒤집는다
**결정**: `수동 Move 1건 → 조회 가능한 dist → 재현성·오류 복구 → 추출 자동화` 순으로 간다. 범용 기반을 먼저 짓지 않는다.
**이유**: 초안의 phase 순서는 수집·참조·인제스트·추출을 다 지어야 소비 가치를 확인할 수 있었다. 손으로 쓴 Move 다섯 개와 조회 가능한 `dist/`만 있으면 **이 KB가 실제 설계 에이전트에 유용한지를 훨씬 적은 구현으로 확인**할 수 있다.
**트레이드오프**: 초기 커버리지가 매우 작다. 계약이 틀렸을 때 버리는 비용도 그만큼 작다.

### ADR-014: 템플릿화는 문자열 금지가 아니라 의존 방향으로 강제한다
**결정**: `engine/`에 도메인 문자열이 없는지 검사하는 대신, **일반 모듈이 도메인 코드에 의존하지 않는지**를 검사한다. 별도 `domain/_template/`을 만들지 않고, 두 번째 도메인은 실제 요구가 생겼을 때 포크해서 검증한다.
**이유**: 엔진/도메인 분리는 새는 지점이 있다. 온톨로지의 *모양*이 kinase 고유이고, Move 스키마는 med-chem 고유이며, `sync-ref`는 100% 도메인 고유다. 문자열 검사는 이 누수를 잡지 못하면서 우회만 유도한다. 실제로 중요한 것은 의존 방향이다.
**트레이드오프**: "포크하면 된다"는 주장이 두 번째 도메인이 생기기 전까지 증명되지 않는다. 플러그인 등록과 추상 기반 클래스를 갖춘 프레임워크를 만드는 것보다는 낫다. 300줄짜리 정직한 물건이 3,000줄짜리 부채가 되면서 여전히 새는 것이 최악이다.
