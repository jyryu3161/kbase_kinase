# PRD: kbase_kinase

## 목표

kinase-ligand 복합체를 보고 다음 화학구조 변형을 제안하는 agent에게, 그 제안의 근거가 될 전례를 공급하는 지식베이스를 만든다.

한 줄로 압축하면: **"이 포켓의 이 위치에서 이런 변형을 시도한 전례가 있는가, 결과와 대가는 무엇이었는가"에 답하는 것.**

이건 제품(product)이 아니라 지식 자산이다. 사용자 경험을 최적화하는 것이 아니라, 추출된 정보가 정확히 관리되는 것이 성공 기준이다.

---

## 사용자

### 1차 사용자: 소비자 agent (기계)

protein-ligand 복합체를 분석하는 multi-modal LLM agent다. 이 저장소를 clone하고 `dist/`의 JSONL과 reader를 통해 질의한다. 구조 해석은 스스로 하고, 전례만 받아간다.

이 사용자가 필요한 것:

- 구조 descriptor를 던지면 해당하는 Move를 돌려받는 것
- 왜 매칭됐는지 구분해서 받는 것 (같은 target / 같은 위치 다른 target / 같은 태그)
- 수치를 잘못 믿지 않도록 조건과 부등호 정보를 받는 것
- 인용할 때 PMID와 원문 위치를 받는 것
- 모르는 것을 모른다고 듣는 것

### 2차 사용자: 프로젝트 소유자 (사람)

논문 PDF를 확보해 `inbox/`에 넣고, 생성된 wiki로 KB 상태를 눈으로 훑는다. 검수는 하지 않는다.

이 사용자가 필요한 것:

- PDF를 파일명 규칙에 맞춰 넣고 명령 하나 실행하면 반영되는 것
- 어떤 PMID를 구해야 하는지 우선순위가 붙은 목록을 받는 것
- KB가 지금 무엇을 알고 무엇을 모르는지 wiki로 보는 것
- 무엇이 검사를 통과하지 못했는지 분리해서 보는 것

### 3차 사용자: 다른 도메인 KB를 만들려는 사람

`src/kbase/`를 복사하고 `src/domains/` 아래 폴더 하나를 새로 채워 같은 구조의 지식베이스를 만든다.

## 핵심 기능

### F1. 문헌 후보 수집 (3경로)

Biopython Entrez로 PMID 후보를 모으고 우선순위를 붙여 PDF 요청 목록을 만든다.

1. 전략축 리뷰 논문을 시드로 잡고 참고문헌을 전개해 primary 후보를 얻는다
2. medchem 저널에 전략축 쿼리를 직접 돌린다
3. KLIFS의 리간드 결합 구조에서 해당 구조를 보고한 논문을 역추적한다

세 경로의 교집합에 있는 논문이 Move 밀도가 가장 높으므로 상위로 정렬한다. 우선순위는 배제 기준이 아니라 정렬 기준이다.

산출물: `PMID, 제목, 저널, 연도, DOI, PMC 여부, 경로, 점수`가 담긴 CSV.

### F2. 전체 kinome reference 계층

외부 스냅샷에서 기계적으로 생성한다. LLM도 사람도 손대지 않는다.

kinase마다 도메인 경계, 85-residue KLIFS pocket 서열, 그리고 구조 앵커(gatekeeper, hinge, DFG, catalytic Lys, αC Glu, solvent front, P-loop)를 담는다. 필드마다 출처 스냅샷을 기록하고, 소스가 엇갈리면 `conflicts`에 양쪽을 남긴다.

처음 보는 kinase에 대해서도 좌표를 제공하는 것이 목적이다. 모르면 `unmapped`로 말한다.

### F3. 구조 계층

`pdb_id + chain + ligand` 단위로 구조별 레코드를 만든다. DFG와 αC 상태를 KLIFS와 Kincore 양쪽에서 받아 대조하고, 엇갈리면 `agreement: conflict`로 남긴다. KLIFS의 서브포켓 boolean 15종과 상호작용 지문, SIFTS 잔기 번호 매핑을 함께 담는다.

kinase가 아니라 구조에 상태를 붙이는 것이 핵심이다. "EGFR은 DFG-in이다"는 거짓이다.

### F4. PDF 투입과 파싱

`inbox/PMID_12345678.pdf`를 넣고 `kb ingest`를 실행한다. 파일명이 규칙을 벗어나면 첫 페이지에서 DOI나 제목을 읽어 PubMed로 조회해 스스로 맞춘다. 실패분만 따로 모아 보고한다.

MinerU로 파싱하고, 같은 PDF를 Docling으로 한 번 더 파싱한다. 두 결과를 수치 대조용으로 보관한다.

### F5. Move 추출

OpenRouter `deepseek/deepseek-v4.1-flash`에 structured outputs를 강제해 Move 후보를 뽑는다. 구조 관찰, 화학적 변경, 효과와 assay 조건, trade-off, 태그, 근거 위치, 25단어 이하 인용을 채운다.

없는 정보는 추측하지 않고 `not_reported`로 기록한다.

### F6. 기계 검사 9종

사람 검수가 없으므로 이것이 유일한 안전망이다.

스키마 검증, quote 실재 확인, 두 파서 수치 대조, ChEMBL 3차 대조, PMID 실재, 구조 참조 실재, 태그 어휘 준수, 부등호 일관성, 중복 탐지.

전부 통과한 것과 하나라도 실패한 것을 `dist/`에서 파일로 분리한다.

### F7. Mutation 계층

내성 변이를 독립 레코드로 둔다. 위치 주석, 영향받는 약물, 극복한 Move 참조, 다른 target의 같은 KLIFS 위치 변이(전이 가설로 표시).

`overcome_by`가 비었다는 것과 변이를 모른다는 것을 reader가 구분해 응답한다.

### F8. dist 빌드와 소비 계약

`moves.jsonl`, `moves_flagged.jsonl`, `structures.jsonl`, `references.jsonl`, `mutations.jsonl`, `figures.jsonl`, `tactics.jsonl`, `manifest.json`, `CONTRACT.md`를 생성해 저장소에 커밋한다.

빌드는 네트워크를 쓰지 않는다. 임시 디렉터리에서 만들고 원자적으로 교체한다. 실패하면 마지막 정상 dist를 유지한다.

### F9. reader

`get`, `find`, `cite`, `tactics`, `reference`, `structure`, `mutation`. 구조 descriptor를 태그와 위치 필터로 변환하고, 매칭 이유를 세 범주로 구분해 돌려준다.

### F10. wiki 3축 생성

kinase별 페이지, 태그 조합별 집계 페이지, 논문별 페이지. 모두 JSONL에서 생성되는 파생물이며 정본이 아니다. 페이지마다 front matter에 생성 시각, 빌드 해시, 소스 레코드 ID, 그리고 미검수 경고를 박는다.

## 하지 않을 것

범위를 명시적으로 닫는다.

- **구조 해석.** 접촉 계산, 포켓 판정, 복합체에서 descriptor를 만드는 일은 소비자 agent가 한다. 이 저장소는 외부 DB의 주석을 가져올 뿐 직접 구조를 분석하지 않는다.
- **사람 검수 워크플로우.** 승인 UI, 검수 큐, reviewer 역할을 만들지 않는다.
- **산문형 설계 규칙.** "언제 쓰고 언제 피하라"를 LLM이 쓰게 하지 않는다. 집계만 제공한다.
- **벡터 DB와 임베딩 검색.** 현재 규모(수백 레코드)에 과하고, 구조화된 필터가 더 정확하다.
- **자연어 질의 인터페이스.** descriptor JSON으로만 받는다. 번역 단계는 재현성을 깨뜨린다.
- **웹 UI.** 사람이 보는 인터페이스는 생성된 마크다운 wiki가 전부다.
- **PDF 자동 수집.** 저작권과 접근 제한 때문에 PDF 확보는 사람이 한다.
- **범용 kinase 위치 매퍼.** 임의 서열에 85-residue 번호를 매기는 범용 매퍼를 직접 만들지 않는다. 외부 스냅샷에 있는 것을 쓰고, 없으면 `unmapped`로 둔다.
- **화합물 구조 표준화와 substructure 검색.** SMILES는 논문에 있으면 기록만 한다. RDKit 기반 검색은 범위 밖이다.
- **ADMET 예측, 도킹, 시뮬레이션.**
- **상업적 재배포.** 저장소는 비공개다. 공개 전환을 대비해 quote를 제외한 export 경로만 준비한다.

## 완료 기준

### 1단계: 논문 3편으로 계약 검증

전기가 통하는지 확인하는 단계다. 여기서 드러날 설계 결함을 30편 처리한 뒤에 발견하면 전부 다시 돌려야 한다.

1. Move가 생성되고 `checks` 9종이 전부 기록된다
2. 관찰, 변형, 효과를 원문 페이지와 표 위치로 되짚을 수 있다
3. 예제 질의 5개가 답한다. 결과가 없어야 정상인 질의와 `unknown` 포함 부정 질의를 넣는다
4. KLIFS/Kincore 충돌 구조 하나에서 `conflict`가 소비자까지 전달된다
5. 재실행 시 `kb/`와 `dist/`가 동일하다
6. 잘못된 PDF 하나가 기존 KB를 손상시키지 않는다

### 2단계: 논문 10편 이상

7. 태그 조합별 집계가 의미 있는 숫자를 갖는다. 전례 1건짜리 조합만 나열되면 실패다
8. 전체 kinome reference가 채워져 있고, 처음 보는 kinase에도 좌표를 돌려준다

reference 계층은 1단계에서 이미 전체 kinome을 채운다. 문헌과 독립적이므로 기다릴 이유가 없다.

## 비기능 요구

| 항목 | 요구 |
|---|---|
| 재현성 | 같은 입력으로 재실행 시 `kb/`와 `dist/`가 바이트 단위로 동일 |
| 오프라인 빌드 | `kb build`는 네트워크를 쓰지 않는다. 외부 접근은 `sync-ref`에만 |
| 원자성 | 빌드 실패 시 마지막 정상 `dist/`가 남는다 |
| 재개 | 중단된 실행은 실패 ID만 기록하고 재실행으로 이어붙인다 |
| 동시성 | 단일 writer. 동시 실행은 잠금 파일로 막는다 |
| 저작권 | PDF와 그림은 git 밖. quote 25단어 이하 |
| 비용 | 추출 모델은 입력 100만 토큰당 $0.15~0.22 수준. 캐시로 재처리 비용을 0으로 만든다 |
| 언어 | 레코드는 영어, 문서는 한국어 |

## 디자인

사람이 보는 산출물은 생성된 마크다운뿐이므로 시각 디자인 요구는 없다. `docs/UI_GUIDE.md`는 이 프로젝트와 무관해 삭제했다.

wiki 페이지의 편집 방향만 정한다.

- 페이지 맨 위 front matter에 생성 시각, 빌드 해시, 소스 레코드 ID, 미검수 경고를 박는다
- 수치는 표로, 서술은 문장으로. 부등호와 assay 조건을 수치 옆에 붙인다
- 검사 실패 레코드는 같은 페이지에 섞지 않고 별도 섹션으로 분리한다
- 링크는 레코드 ID로 건다. 파일 경로로 걸지 않는다
